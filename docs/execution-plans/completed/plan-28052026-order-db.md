## Key Findings

### 1. Shopify product identifier in `products` table
- `products.external_id` = `BIGINT UNSIGNED` = Shopify product ID
- **No variant ID stored** — `order_items.product_id` can only link by `shopify_product_id`, not by variant

### 2. Migration style
- Schema source of truth: `apps/backend/src/db/schema.ts`
- Generate migration: `pnpm --filter @price-insight/backend db:generate` → creates `drizzle/000N_*.sql`
- Apply migration: `pnpm --filter @price-insight/backend db:push` or `run-migrations.ts`
- `migrate.ts` is a manual dev-reset script (drops + recreates all tables) — must also be updated to include new tables

### 3. Drizzle patterns in use
- Shopify IDs: `bigint(col, { mode: "number", unsigned: true })`
- Money: `decimal(col, { precision: 12, scale: 4, mode: "number" })` via shared `moneyColumn` const
- Timestamps: `timestamp(col)` with `.defaultNow()` / `.onUpdateNow()`
- Upsert: select by unique key → update if exists, `$returningId()` insert if new

### 4. Shopify service gaps
- `ShopifyService` only has `getAccessToken()` and `fetchAllProducts()`
- No orders endpoint — needs `fetchOrders(accessToken, updatedAtMin?)` with pagination
- Env: `SHOPIFY_ORDERS_URL` needs to be added (not in env schema yet)

### 5. Existing route pattern (`POST /api/products/sync`)
- New `POST /api/orders/sync` should follow exact same pattern

## Implementation Plan

### Step 1 — Schema (`schema.ts`)
Add 4 tables following existing patterns:

```
customers          — shopify_customer_id BIGINT UNSIGNED unique
customer_addresses — shopify_address_id BIGINT UNSIGNED unique nullable, FK → customers
orders             — shopify_order_id BIGINT UNSIGNED unique, FK → customers nullable
order_items        — shopify_line_item_id BIGINT UNSIGNED unique, FK → orders, FK → products nullable
```

Money columns (`subtotal_price`, `total_price`, `total_tax`, `total_shipping`, `total_discounts`, `unit_price`, `total_discount`) all use `moneyColumn`.

### Step 2 — Generate migration
```bash
pnpm --filter @price-insight/backend db:generate
```
Review generated SQL, then update `migrate.ts` manually with matching CREATE TABLE blocks.

### Step 3 — `OrderRepository`
Methods:
- `upsertCustomer(data)` — by `shopify_customer_id`
- `upsertCustomerAddress(data)` — by `shopify_address_id` (nullable → skip if null)
- `upsertOrder(data)` — by `shopify_order_id`
- `upsertOrderItems(orderId, items[], productLookup)` — by `shopify_line_item_id`
- `getLastSyncedAt()` — `SELECT MAX(shopify_updated_at) FROM orders`
- `importOrders(shopifyOrders[])` — orchestrates all upserts, builds productLookup map from `products` table

### Step 4 — Extend `ShopifyService`
Add `fetchOrders(accessToken, updatedAtMin?: string): Promise<ShopifyOrder[]>` — same pagination loop as `fetchAllProducts`, with `?updated_at_min=` query param if provided.

Add Shopify order/customer/line_item TypeScript types.

### Step 5 — `orders.ts` route
```
POST /api/orders/sync
  → getLastSyncedAt()
  → shopifyService.fetchOrders(token, lastSyncedAt)
  → orderRepository.importOrders(orders)
  → return { synced: N }
```

### Step 6 — Wire in `app.ts`
- Instantiate `OrderRepository`
- Conditionally guard `shopifyService` (same as products route)
- Register `ordersRoutes` with `{ prefix: "/api" }`

### Step 7 — Tests
Follow `product-repository.test.ts` mock-DB pattern. Cover all 11 test cases from the task spec.

## Risks

| Risk | Severity | Mitigation |
|---|---|---|
| No Shopify variant ID in `products` — can only link order_items by product ID, not variant | Low | Match on `shopify_product_id` only; keep `product_id` nullable as spec requires |
| `decimal` with `mode: "number"` can lose JS precision for large values | Low | DECIMAL(12,4) is stored precisely in MySQL; acceptable for order totals |
| `customer_id` on orders is nullable — guest checkout orders have no customer | Low | Task spec marks it nullable; handle in upsert |
| `shopify_address_id` nullable — some addresses may lack an ID | Low | Skip address upsert when null |
| `migrate.ts` reset script must be kept in sync manually | Medium | Update it in the same PR |
| `SHOPIFY_ORDERS_URL` may need to be a separate endpoint or derived from a base URL | Low | Add as independent optional env var |
